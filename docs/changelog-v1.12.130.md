# KeePlus / auto-dba v1.12.130

相对 [v1.12.129](changelog-v1.12.129.md)。工单创建后，通知开关关闭、配置读失败或配置解析失败时也会写入查询审计。查询审计可以用页面上的工单名搜到记录，列表直接显示失败原因。工单详情展示这次待审批通知的结果。飞书通讯录同步纳入内置 admin。无表结构变更，无 Agent 协议变更。

## 工单通知

- 四个「工单创建」开关都关闭、读取通知配置失败、配置 JSON 解析失败、没有审批人时，各写一条通知审计，不因此发送消息。只开群机器人且没有审批人时同样留记录，机器人仍按原方式发送。
- 审计写入失败时，日志包含工单号、审批人和错误原文。
- 查询审计关键字带 `DQL-`、`DDL-` 等已知工单类型前缀时，同时按去掉前缀后的工单号匹配。只搜真实工单号或其它关键字时，结果不变。
- 查询审计列表增加「说明」列，失败原因不用点开语句。
- 工单详情在申请信息上方显示待审批通知是成功还是失败。没有记录时提示可能是旧版本或审计写入失败，请查平台日志。

## 飞书同步

- 内置 admin 参与通讯录同步。仍要求已登录，并按飞书邮箱、企业邮箱、手机号匹配 open_id。
- 用户列表对 admin 显示已同步、未同步或未登录，不再固定为「-」。

## 打包与发版

```bash
STAMP=v1.12.130 ./scripts/pack_release.sh all
# 本地标签（本发版未 push / 未发 GitHub Release）：
# git tag -a v1.12.130 -m "v1.12.130"
```

部署见 [deploy.md](deploy.md)。一体包含本版构建的全部 Agent 二进制。本次未改 Agent 协议。已经用 v1.12.124 及以后包下发过的 SQL 执行器不必为这个版本重装；若执行器仍是 v1.12.123 及更早，须用 v1.12.124 或本版包重下发。工单通知和 admin 飞书同步要使用本版平台进程与前端，请重启平台并刷新页面。重启后再同步一次飞书通讯录，admin 才会写入 open_id。已有元库不用补表。
