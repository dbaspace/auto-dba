# 登录会话监控 · 二期方案（文档预留，本期不开发）

一期能力见实现与 [nacos-config.md](nacos-config.md) 中 `redis:` 段：按用户维度 Redis 会话、`会话有效` 语义、管理端「登录会话」、用户「我的登录」、写序 Redis→元库、定时对账。

以下条目**不纳入一期交付**，供后续排期。

## 二期目标

在「会话有效」之上，补齐**活跃感知、更强安全、实时运营与合规导出**，仍尽量控制元库写放大（活跃态以 Redis 为主）。

## 二期-1：真·活跃在线（页面存活）

| 项 | 说明 |
|----|------|
| 产品 | 区分「会话有效」与「当前活跃」；列表可筛「仅活跃」；头像/角标可选绿点 |
| 机制 | 前端低频 heartbeat（建议 ≥2–5 分钟，页面可见时才发）；Redis `autodba:user:{uid}:active` 或用户 Hash 内 `active:{jti}` 短 TTL（如 10min）；**不写元库** |
| 展示 | 管理列表增加列「最近活跃」；人数可拆「有效会话 / 活跃会话」 |
| 约束 | 可配置关闭 heartbeat；默认关闭或仅管理端展示活跃列 |

## 二期-2：会话安全增强

| 项 | 说明 |
|----|------|
| 单端登录默认策略 | 租户/全局策略：新登录踢旧；或同端类型互踢（Web/API） |
| 异地/异常登录 | 登录 IP/UA 与常用画像差异时：通知或强制二次验证 |
| Refresh Token | 短 access JWT + Redis refresh；刷新时轮换 jti |
| HttpOnly Cookie | 评估 Cookie 下发 + CSRF，替代 localStorage |
| 设备指纹（可选） | device_id 写入会话；异常设备一键下线 |

## 二期-3：运营实时与可观测

| 项 | 说明 |
|----|------|
| WebSocket/SSE | 管理端订阅会话变更；失败回退轮询 |
| 工作台组件 | 「有效会话数 / 活跃数 / 近 1h 登录失败」 |
| 告警 | 同账号短时多地登录、单 IP 大量账号等 |
| 审计增强 | 登录原因、踢人者、模拟登录起止时间线 |

## 二期-4：合规与导出

| 项 | 说明 |
|----|------|
| 导出 | 按时间/租户异步导出会话最终态与踢人记录 |
| 留存策略 | 热数据 Redis TTL；冷数据元库 N 天；超期清理配置化 |
| 租户隔离加强 | 租户管理员仅本租户；平台超管跨租户 |

## 依赖与风险

- Refresh / Cookie 需安全评审与旧 token 兼容窗口。
- Heartbeat 与 WebSocket 增加连接数，需按峰值评估。
- 异地二次验证依赖通知渠道或 SSO step-up。
